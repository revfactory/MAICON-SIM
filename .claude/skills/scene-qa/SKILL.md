# 씬 QA — 스펙과 실물의 교차 대조

3D 씬 검수가 실패하는 전형적 방식은 **"존재 확인"으로 끝내는 것**이다. "객체 23개가 생성되었다"는 좌표가 100배 틀려도, 전부 땅에 묻혀 있어도, 좌우가 반전되어 있어도 똑같이 참이다. 개수는 오류를 거의 잡지 못한다.

이 스킬의 원칙은 하나다: **스펙과 실제 씬을 같이 열어 값을 대조한다.** 어느 한쪽만 보면 불일치는 원리적으로 보이지 않는다.

## 1. 검수 시점 — 각 단계 직후

전체 빌드가 끝난 뒤 한 번에 검수하면 초기 오류가 이후 단계로 전파되어 수정 비용이 폭증한다. 좌표계가 반전된 채 트랙을 만들면 건물·객체·경로·카메라가 전부 그 위에 쌓인다.

**각 스크립트 실행 직후 해당 단계를 검수한다.** 단계별 필수 확인 항목은 6절에 있다.

## 2. 자동 대조 — `verify_scene.py`

번들된 `scripts/verify_scene.py`를 Blender에서 실행하면 스펙 대비 씬 상태를 자동 대조하고 결과를 JSON으로 돌려준다. 매번 검증 코드를 새로 짜지 말고 이것을 쓴다.

```python
exec(open("/Users/robin/Downloads/maicon-sim/.claude/skills/scene-qa/scripts/verify_scene.py").read())
```

대조 항목:
- 스펙의 모든 좌표 ↔ 씬 오브젝트의 실제 위치 (허용 오차 1 mm)
- 필수 오브젝트 존재 여부 (이름 규약 기준)
- `.001` 접미사가 붙은 오브젝트 (재실행 시 purge 누락 신호)
- 경기장 경계 이탈 (`|x| > 2.5` 또는 `|y| > 1.75`)
- 노면 관통/부유 (바닥 오브젝트의 Z가 음수이거나 5 mm 초과)
- 머티리얼 미할당 오브젝트
- 오브젝트 간 바운딩박스 겹침
- 개수 검증 (객체 23, 포트홀 2, 배리어 2, 섹터 9, 체크포인트 3)

**자동 대조는 필요조건이지 충분조건이 아니다.** 수치가 전부 맞아도 룩이 엉망일 수 있다. 3절의 시각 판독을 반드시 병행한다.

## 3. 시각 판독 — 두 각도를 모두 본다

한 각도만 보면 절반의 오류를 놓친다. **톱 뷰에서 완벽해 보이는 씬이 옆에서 보면 전부 공중에 떠 있을 수 있다.**

| 뷰 | 잡는 오류 |
|-----|----------|
| **톱 뷰(직교)** | 좌우/상하 반전, 배치 위치, 겹침, 경계 이탈, 도면과의 대조 |
| **낮은 각도 원근** | Z 오프셋(묻힘/부유), 스케일 오류, 그림자 누락, 관통 |
| **카메라 뷰** | 최종 룩, 프레이밍, 라이팅 |

톱 뷰 전환 코드는 `blender-mcp-protocol` 스킬 11절에 있다.

**프레이밍 판단에 뷰포트 스크린샷을 쓰지 마라.** 카메라 뷰의 뷰포트 스크린샷은 카메라 프레임 **바깥 영역까지** 함께 보여준다(패스파트아웃이 꺼져 있으면 경계선도 없다). 그래서 실제 렌더보다 피사체가 훨씬 작게 보이고, "구도가 헐겁다"는 잘못된 판단을 부른다.

카메라 구도는 두 가지 중 하나로 판단한다:
- **단일 프레임 렌더** — EEVEE는 프레임당 1~3초라 저렴하다. 이것이 정답이다
- **투영 좌표 측정** — `bpy_extras.object_utils.world_to_camera_view`로 대상의 화면 좌표(u, v)를 직접 잰다. `u, v ∈ [0,1]`이 화면 안이고, 0.5가 중앙이다

```python
from bpy_extras.object_utils import world_to_camera_view as w2c
uv = w2c(scene, cam, Vector((0, 0, 0.12)))   # 경기장 중심이 화면 어디에 오는가
```

**"화면 안에 있는가"를 오브젝트 원점으로 판정하지 마라.** 원점이 프레임 안이어도 바운딩박스는 잘릴 수 있다 — 차량 클로즈업에서 앞뒤가 잘린 것을 "화면내 11/11"로 통과시킨 실제 사례가 있다. 바운딩박스 8점을 모두 투영해 확인한다.

**톱 뷰 스크린샷은 원본 도면과 직접 비교한다.** 이것이 축 반전을 잡는 가장 확실한 방법이다. START가 좌상단, FINISH가 우하단에 있는지, 섹터 배치가 도면과 같은 방향인지 눈으로 확인한다. 수치 검증만으로는 "스펙 자체가 반전되어 있는" 경우를 잡을 수 없다.

## 4. 이 도메인의 전형적 결함

실측 스케일(1 unit = 1 m)에서 5 m 경기장을 다루는 데서 오는 고유한 오류들이다.

| 결함 | 증상 | 원인 | 확인법 |
|------|------|------|-------|
| **단위 혼동** | 물체가 거대하거나 안 보임 | mm 값을 m로 씀 (1000배) | `obj.dimensions` 출력. 경기장이 5.0인지 |
| **축 반전** | 좌우/상하가 거울상 | 픽셀→월드 변환에서 Y 부호 누락 | 톱 뷰 ↔ 도면 비교 |
| **Z 오프셋** | 물체가 묻히거나 뜸 | 원점이 중심에 있는데 Z=0 배치 | 낮은 각도 뷰. 바운딩박스 최소 Z 확인 |
| **Z-파이팅** | 노면 마킹이 얼룩덜룩 | 마킹과 노면이 같은 높이 | 톱 뷰 확대. 마킹 Z가 0.0005인지 |
| **이름 충돌** | 참조가 조용히 실패 | purge 없이 재실행 → `.001` | 이름에 `.` 포함 오브젝트 검색 |
| **머티리얼 미할당** | 전부 회색 | `use_nodes` 누락 또는 슬롯 비어 있음 | `len(obj.material_slots) == 0` 검색 |
| **개수 부족** | 22개만 배치됨 | 루프에서 예외 조용히 삼킴 | 스펙 개수와 실제 개수 대조 |
| **애니메이션 정지** | 차량이 안 움직임 | 컨스트레인트 타깃 누락 / eval_time 키 없음 | 여러 프레임에서 위치 샘플링 |
| **카메라 클리핑** | 근접 샷에서 물체 잘림 | `clip_start` 기본값 0.1 m | 카메라 뷰 스크린샷 |

## 5. 애니메이션 검증 — 프레임을 샘플링한다

정지 상태 확인만으로는 애니메이션 오류를 잡을 수 없다. 여러 프레임에서 위치를 실측한다.

```python
positions = []
for f in range(1, scene.frame_end + 1, 20):
    scene.frame_set(f)
    positions.append((f, tuple(root.matrix_world.translation)))
```

확인 항목:
- 위치가 실제로 변한다 (전부 같으면 애니메이션 미적용)
- 경로 진행이 **단조**다 (후진 구간이 있으면 `eval_time` 키가 역전된 것)
- 체크포인트 최근접 거리가 0.05 m 이내다
- 포트홀 최근접 거리가 0.085 m 이상이다
- Z가 일정하다 (바닥을 뚫거나 뜨지 않음)

`scene.frame_set(f)`를 호출해야 컨스트레인트가 평가된 실제 위치를 읽는다. 이것 없이 `matrix_world`를 읽으면 모든 프레임이 같은 값으로 나와 "애니메이션 없음"으로 오진한다.

## 7. 리포트 형식

검수 결과는 `_workspace/qa/{NN}_{module}_report.md`에 기록한다. 구두 보고만 하면 무엇이 미검증으로 남았는지 추적되지 않는다.

```markdown
# QA: 40_sectors

## 통과 (5)
- 섹터 9개 생성 확인 (SEC_01 ~ SEC_09)
- 높이 변주 확인 (0.36 ~ 0.55)
...

## 실패 (1)
- **SEC_04 좌표 불일치**: 스펙 (1.85, 0.75) ↔ 실제 (1.85, -0.75)
  - 원인 추정: Y 부호 오류
  - 요청 대상: asset-modeler
  - 수정 방법: `40_sectors.py`의 SEC_04 배치에서 spec 값을 그대로 사용

## 미검증 (1)
- 건물 창문 스트라이프 — 뷰포트 Solid 셰이딩이라 확인 불가. Material Preview 전환 필요
```

**통과·실패·미검증을 반드시 구분한다.** "확인하지 못한 것"을 "통과"에 섞으면 리포트 전체의 신뢰가 사라진다.

## 8. 수정 요청 프로토콜

검수관은 씬을 직접 고치지 않는다. 고치면 스크립트와 실제 씬이 어긋나 재현성이 깨지고, 다음 재빌드에서 수정이 사라진다.

발견 시 **담당 에이전트에게 수정할 스크립트와 방법을 명시해 요청**한다:

| 결함 영역 | 담당 | 수정 대상 |
|----------|------|----------|
| 좌표 스펙 자체 | track-surveyor | `track_spec.json` |
| 노면·차선·포트홀·배리어 | track-builder | `10~30_*.py` |
| 건물·객체·마커·차량 | asset-modeler | `40/50/60/70_*.py` |
| 객체 배치 | scene-dresser | `55_placement.py` |
| 주행 경로·애니메이션 | motion-director | `80_motion.py` |
| 카메라·라이팅·렌더 | cinematographer | `90/95_*.py` |

**좌표 불일치는 두 곳을 모두 의심한다.** 스펙이 틀렸을 수도, 스크립트가 스펙을 잘못 읽었을 수도 있다. 어느 쪽인지 판단해서 요청해야 엉뚱한 곳을 고치지 않는다.
