# 트랙 좌표 원본 — MAICON 본선 경기장

이 파일이 트랙 좌표의 **단일 진실 공급원**이다. 다른 스킬·스크립트는 좌표를 새로 추정하지 않고 여기서 가져온다. 값이 틀렸다고 판단되면 이 파일을 고치고, 고친 근거를 "판독 이력"에 남긴다.

아래 좌표는 도면 이미지에서 1차 판독한 값이다. `track-surveyor`가 도면을 재확인해 정밀화한 뒤 `_workspace/spec/track_spec.json`으로 확정한다.

## 1. 좌표계와 변환식

- 원점: 경기장 정중앙
- X: 도면 가로, 오른쪽 +, 범위 `-2.50 ~ +2.50` (5.0 m)
- Y: 도면 세로, 위쪽 +, 범위 `-1.75 ~ +1.75` (3.5 m)
- Z: 높이, 노면 = 0

도면 이미지는 2000 × 1400 px 기준이며 5:3.5 = 1.4286으로 경기장 비율과 정확히 일치한다. 따라서 변환이 선형이다:

```
x_m = (px / 2000) * 5.0 - 2.5
y_m = 1.75 - (py / 1400) * 3.5
```

다른 해상도의 도면을 쓸 때는 위 식의 2000/1400을 실제 픽셀 크기로 바꾼다. 비율이 1.4286에서 벗어나면 도면이 잘렸거나 여백이 있는 것이므로, 경기장 테두리를 기준으로 크롭한 뒤 변환한다.

## 2. 검산 규칙

판독 좌표를 확정하기 전에 반드시 통과해야 하는 조건이다. 이 검산을 건너뛰면 좌우 반전이나 Y축 부호 오류가 끝까지 살아남아 트랙 전체가 거울상이 된다.

- [ ] 모든 좌표가 `|x| ≤ 2.5`, `|y| ≤ 1.75` 안에 있다
- [ ] START는 좌상단 (`x < -2.0`, `y > 1.0`), FINISH는 우하단 (`x > 2.0`, `y < -1.5`)
- [ ] ALPHA는 상단(`y > 1.5`), CHARLIE는 하단(`y < -1.5`), BRAVO는 중앙부(`|y| < 0.3`)
- [ ] Sector 1·2는 상단 좌중앙, Sector 3·4는 상단 우측, Sector 7은 좌하단, Sector 9는 우하단
- [ ] 헬리패드는 좌상단, START 아래
- [ ] 체크포인트 3곳이 모두 주행 경로 위 또는 경로에서 0.15 m 이내

## 5. 주행 경로 구조

노란 선은 차선 경계이며, 위상은 다음과 같다:

- **외곽 순환로 1개** — 경기장 가장자리를 따라 도는 큰 루프. 네 모서리는 라운드 처리
- **섹터 서브 루프 4개** — 각 섹터 클러스터(A/B/C+D/E)를 감싸는 내부 루프
- **중앙 십자 교차로** — 세로선 `x ≈ 0.56`, 가로선 `y ≈ 0.18`에서 교차. 흰 선으로 표시

**UGV 주행 라인** (START → FINISH, 체크포인트 3곳 경유)의 근사 제어점. 아래는 2026-08-01 정밀화를 반영한 **확정 22점**이며, `track_spec.json`의 `path`와 동일하다:

```
START      (-2.35,  1.33)
  ↓ 상단 직선 진입
           (-1.80,  1.60)
ALPHA      (-1.15,  1.63)   ← 체크포인트 1
           ( 0.40,  1.60)
  ↓ 우측 곡선
           ( 1.90,  1.45)
           ( 2.30,  0.90)
           ( 2.25,  0.30)
  ↓ 중앙 십자 회랑 진입 (SEC 5·6 북측 우회)
           ( 1.70,  0.19)
           ( 0.56,  0.18)   ← 중앙 십자 교차로
           (-0.15,  0.20)
BRAVO      (-0.39, -0.13)   ← 체크포인트 2
  ↓ 북서로 복귀 후 좌측 하강
           (-0.70,  0.10)
           (-0.95,  0.42)   ← 포트홀 1 북측 우회
           (-1.62,  0.38)
           (-2.08,  0.05)
           (-2.15, -0.70)
           (-2.20, -1.35)
CHARLIE    (-1.55, -1.64)   ← 체크포인트 3
  ↓ 하단 직선
           (-1.05, -1.68)   ← 포트홀 2 남측 우회
           ( 0.50, -1.68)
           ( 1.60, -1.68)
FINISH     ( 2.23, -1.68)
```

1차 판독의 중앙부 3점 `(1.20, 0.05)` `(0.30, -0.10)` `(-1.60, -0.20)`은 **폐기**했다. 각각 Sector 5 풋프린트 상단을 스치고, Sector 6 풋프린트 내부를 관통하며, Sector 7 객체군(포지션 12·13) 사이를 통과해 주행이 불가능하다. `(1.60, -1.70)`은 차체 절반(0.065 m)을 더하면 아레나를 벗어나므로 `-1.68`로 올렸다.

이 제어점은 **주행 라인의 개형**이다. 실제 애니메이션 경로는 `motion-director`가 베지어로 다듬되, 체크포인트 3곳과 START/FINISH는 반드시 통과해야 한다. 포트홀 2곳은 회피 대상이므로, 경로가 포트홀 반경 + 차폭 절반보다 가깝게 지나가면 우회 제어점을 추가한다.

**확정 시점 클리어런스** (제어점 폴리라인을 10 mm 간격 샘플링, 차폭 절반 0.065 m 기준):

| 항목 | 최소 클리어런스 | 필요치 |
|------|---------------|-------|
| 섹터 풋프린트 | 0.110 m (SEC 6) | 0.065 |
| 객체 23곳 | 0.204 m (포지션 16) | 종류별 r + 0.065 |
| 포트홀 1 / 2 | 0.229 / 0.200 m | 0.175 / 0.165 |
| 배리어 1 / 2 | 0.155 / 0.217 m | 0.065 |

경로 총 길이 16.35 m.

## 6. 판독 정밀화 절차

1. 도면 이미지를 다시 확인하고, 각 요소의 픽셀 좌표를 재측정한다
2. 2절의 검산 규칙을 전부 통과시킨다
3. 이 파일의 표를 갱신한다 (근거를 7절에 기록)
4. `_workspace/spec/track_spec.json`을 생성/갱신한다
5. 톱 뷰 렌더와 원본 도면을 나란히 비교해 최종 확인한다

**좌표가 애매한 요소**(도면에서 라벨만 보이고 정확한 중심을 알기 어려운 것)는 추측한 값을 쓰되, `track_spec.json`에 `"confidence": "low"` 필드를 붙인다. 나중에 검수 단계에서 우선 확인 대상이 된다. 애매함을 숨기고 확정값처럼 쓰면 어디가 틀렸는지 찾을 수 없게 된다.
